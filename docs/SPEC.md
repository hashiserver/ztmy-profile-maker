# 自己紹介カードメーカー — MVP要件定義書

- 文書版: **v1.8（MVP用統合・レビュー版）**
- 作成日: 2026-10-16
- ステータス: **要件定義の整理完了／実装未着手**
- 対象: 一般ユーザー向けWebアプリおよびテンプレート登録・公開運用

> 本文の「必須」はMVPとして合意済みの機能要件、「実装方針」は現時点の技術選択、「技術検証」は開発開始時に小さく試して確定する内容を意味する。数値が暫定のものはその旨を明記する。新たな機能を追加する際は別途合意する。

## 1. 目的と成功条件

作者が制作した自己紹介カードのテンプレートを選び、ブラウザ内で文字や自分のアイコン画像を入力・調整し、鮮明なPNG画像として保存・共有できる無料サービスを提供する。

**MVPの成功条件**は、スマートフォンとPCで「テンプレート選択 → 入力・アイコン調整 → 完成画像確認 → PNG保存」をアカウント登録なしで完了できること。Xへの投稿は補助機能であり、Xへの画像自動添付・自動投稿までは保証しない。

### 原則【必須】

- 利用者に会員登録・ログイン・課金を要求しない。
- 編集内容とアップロード画像は、基本的に利用者のブラウザ内だけで処理・保存する。アプリケーション用バックエンドやDBサーバーは設けない。
- テンプレートは運営者のみが登録し、一般ユーザーからの投稿は受け付けない。
- 作者の権利とクレジットを尊重し、許諾を確認した画像だけを登録する。
- 運用費は**月額0円を目標**とする。無料枠や提供条件の変更により永続的な無償運用を保証するものではない。
- モバイルファーストで、PCでも操作できる。

## 2. 対象ユーザーと画面

| 役割 | できること |
|---|---|
| 一般ユーザー | テンプレート選択、文字・選択項目入力、アイコンアップロード、編集、下書き復元、PNG保存、共有 |
| 運営者 | 作者との許諾確認、AI支援による設定作成、PRレビュー、公開・更新 |
| テンプレート作者 | 画像・作者プロフィール・掲載条件を提供。専用アカウントは不要 |

**画面【必須】**
1. テンプレート一覧（サムネイル、タイトル、作者アイコン・名前・SNS等へのリンク）。
2. 編集画面（カードプレビュー、項目編集、設定、PNG保存・共有）。編集画面にも作者情報を表示する。
3. サービス説明、利用規約、プライバシーポリシー。

独立した「完成画面」は作らず、編集画面内で完結する。

## 3. テンプレート・作者【必須】

### 3.1 画像とレイヤー

- **完成した背景画像1枚を基本**とする。前面装飾の透過画像は必要な場合だけ追加する。
- 標準描画順: 背景 → 利用者のアイコン → 入力文字・選択マーク → 任意の前面装飾。
- テンプレートの縦横サイズ・比率は固定しない。元画像の実寸を出力基準とする。
- 背景に印刷済みの枠やラベルは基本的に残す。アイコンが枠線やプレースホルダー文字を不自然に覆わないことを公開前に確認する。必要な装飾は前面レイヤーで対応する。

### 3.2 作者情報

- 作者ID、表示名、静的プロフィール画像、外部リンク、任意の紹介文を別データとして管理する。
- 作者アイコン・作者名・リンクはテンプレート一覧と編集画面の両方に表示する。
- X等のSNSアカウントからアイコンを自動取得しない。作者のアイコンは運営者が許諾済み画像を登録する。

### 3.3 フィールド

テンプレートごとに次の種類を組み合わせる。

| 種類 | 必要な設定 |
|---|---|
| 1行／複数行テキスト | 入力ラベル、描画矩形、フォント、色、揃え、行間、文字方向、自動縮小など |
| 単一選択 | 選択肢、マーク位置・見た目 |
| 複数選択・チェック | 選択肢、マーク位置・見た目 |
| アイコン画像 | 円形切り抜き領域、初期配置・拡大率 |

- 各フィールドには安定した一意のIDを付与する。
- 入力領域の座標・寸法は**元画像ピクセル基準**。画面上の表示倍率とは分離する。
- 描画領域とタップ・クリック判定領域は分離できるようにする。
- 表示方向はテンプレート全体の初期値とフィールド単位の上書きで決める。**利用者による縦横切り替えは提供しない。**

## 4. 編集機能【必須】

### 4.1 文字の入力と描画

- テンプレート上の項目を選択して直接編集を開始できる。
- PCではプレビュー上の入力と右側の設定パネルを併用する。
- スマホではプレビュー上で項目を選択し、**下部入力パネルを基本**としてキーボードでプレビューが隠れにくい構成とする。
- 文字変更をプレビューへ随時反映する。日本語変換中の値は破壊しない。
- 手動改行を維持し、自動改行、自動文字サイズ縮小、手動サイズ変更、文字色・フォント・揃え・位置の調整に対応する。
- 文字が枠に収まらない場合は警告するが、PNG保存を禁止したり文字を勝手に削除したりしない。
- **編集確定後のプレビューとPNGの改行・配置は共通の文字レイアウト結果に基づく。** IME変換中のキャレット表示までCanvasと完全一致させることは要求しない。

### 4.2 縦書き

- 初期版から横書きと縦書きに対応する。方向は運営者がテンプレート設定で指定する。
- 縦書きは日本語の標準組版を基本とする。上→下、右→左の行送り。句読点・括弧は縦書き用字形・位置を考慮する。
- 半角2桁の数字は縦中横、英単語は原則90度回転を初期ルールとする。
- 縦書きでも改行・サイズ調整・警告を提供する。
- **技術検証**: Canvas 2D単独かDOM/SVG併用かは、実際に日本語・記号・PNG出力を比較して決める。機能要件は維持する。

### 4.3 フォント

- 初期搭載数は**8〜10種類**。日本語対応の無料フォントから選定する。
- 想定カテゴリはゴシック・丸ゴシック・明朝・手書き風・装飾系。
- 候補: Noto Sans JP、Noto Serif JP、Zen Maru Gothic、M PLUS Rounded 1c、Klee One、Yomogi、Kaisei Decol、Shippori Mincho、Dela Gothic One。
- **候補名は正式採用確定ではない。** 各フォントのライセンス、Web配布・同梱の条件、縦書き適性、必要な表示、容量を検証して選定する。
- 使用フォントだけを遅延読み込みすることを基本とし、読み込み完了後に再レイアウトする。

### 4.4 文字位置調整

- ドラッグおよび矢印ボタンで調整し、初期位置へ戻せる。
- テンプレートで許容された範囲内だけ移動でき、枠外への軽微な移動は認める。
- **暫定初期値**: 元画像1537×2048px程度を想定して横±32px、縦±24px。小さい領域は縮小し、フィールド単位で上書きできる。通常4px、詳細1px単位で調整。
- ドラッグによる位置調整と通常のページスクロールを別モードにする。
- 移動量は元位置からの差分で保存する。

### 4.5 アイコン画像の編集

- 利用者は端末からJPEG・PNG・WebP等の対応画像をアップロードする。
- X API、unavatar、その他の外部プロフィール画像取得サービスは使わない。
- 円形の表示領域を固定し、内部画像をドラッグ・拡大縮小・差し替え・削除・リセットできる。
- スマホではドラッグ・ピンチ、PCではドラッグ・ズーム操作を提供する。
- 切り抜き位置と倍率は下書きに保存し、PNG出力に反映する。

## 5. 画像処理・PNG出力【必須】

- 利用者画像は編集処理のために外部サーバーへアップロードせず、ブラウザ内でデコード・正規化する（本人が明示的に共有操作をした場合を除く）。
- ファイルサイズによる一律の受付上限は極力設けない。ただしブラウザが処理できない寸法・メモリ負荷の画像は安全に拒否し、理由を案内する。
- EXIFによる向きを考慮し、保存する正規化画像には撮影位置など不要なメタデータを持ち越さない。
- 不必要に大きい画像は必要に応じて縮小する。**作業用画像の長辺3072pxは暫定目安**であり、固定のアップロード上限ではない。
- PNGを標準の出力形式とし、テンプレートの元画像サイズで保存する。
- 画像生成に失敗した場合は理由を案内して再試行できるようにする。
- 元画像が極端に大きいテンプレートはCanvasのメモリ・最大寸法を踏まえて運営者が公開前に検証する。

## 6. 下書きの自動保存・復元【必須】

- IndexedDBに**テンプレートごと1件**の下書きを保存する。保存先は利用者のブラウザ。
- 対象: 入力値、選択状態、スタイル、位置調整、正規化したアイコン画像Blob、切り抜き情報、SNS投稿文、スキーマ・テンプレートバージョン、更新日時。
- 文字入力では最後の変更から**約700ms**後を目安に非同期保存し、画像操作確定時にも保存する。
- 保存リビジョン／処理順序を管理し、古い保存が新しい内容を上書きしない。
- 編集画面を再び開いたら、互換性のある最新下書きを**確認ダイアログなしで自動復元**する。
- 下書きの読み込み完了前に空の初期状態を自動保存しない。
- 復元後は控えめな通知を表示する。初期化操作は確認を挟む。
- 互換性が不明な下書きや保存失敗時はデータを破棄せず警告する。
- ブラウザのデータ削除・容量制限によって下書きが失われる可能性を説明する。MVPではファイルバックアップ・複数下書き・端末間同期は実装しない。

## 7. SNS共有【必須】

- 編集画面からPNG保存と共有を実行できる。
- テンプレートごとにハッシュタグ・作者リンク等を含めた投稿文初期値を設定でき、利用者が自由に編集できる。
- 対応端末では、あらかじめ生成したPNGファイルと投稿文をWeb Share APIへ渡す。
- 共有先アプリが画像・テキストを受け取るかは保証しない。
- 代替操作: PNGダウンロード、対応ブラウザでの画像コピー、投稿文コピー、Xの投稿画面を開く。
- X Web Intentは文章の入力補助であり、画像の自動添付には使用しない。X API、自動投稿機能は持たない。

## 8. 公開・テンプレート登録運用【必須】

### 8.1 リポジトリと権利

- GitHubリポジトリは**Public**。
- **画像利用許諾の取得後**にChatGPT/Codexへ登録作業を依頼する。
- 許諾にはWeb掲載だけでなく、公開GitHubへの画像登録、カード画像の生成・保存・SNS投稿、作者情報表示も含めて確認する。
- 公開GitHubへの登録・PR作成時点で画像は第三者に見えること、フォーク・コピーが残り得ることを前提とする。
- 許諾の原文・個人的なDM・メール等は公開リポジトリへコミットしない。公開するのは権利者・表示条件等の必要情報だけにする。
- ソースコードのライセンスと作者提供画像の利用条件を明確に区別する。

#### 2026-10-20の個別対応（ユーザー指示）

`ztmy-heijokyo-2026` の提供画像1件は、作者へ許諾を依頼するための確認版として、許諾取得前に開発ブランチ・Draft PRへ先行登録する。GitHubリポジトリはPublicであり、サイトのリリース前でも画像を閲覧できる。許諾取得済みとは記録せず、作者名・掲載条件とともに未確認として管理する。一般向けサイトの公開前に許諾と作者情報を確定する。この個別指示以外の通常登録フローは維持する。

### 8.2 登録フロー

1. 許諾済みの背景画像・任意の前面装飾・作者情報を準備。
2. ChatGPT/Codexが画像上の入力領域を推定し、テンプレート定義とサムネイルを作成。
3. GitHubにPRを作成。
4. GitHub Actionsでスキーマ・ID・画像参照・座標・ビルド・描画を確認し、座標付き／通常入力／長文などの**確認画像**を生成。
5. 運営者が確認画像、作者情報、権利関係をレビューし、必要なら修正を依頼。
6. 問題なければPRをマージし、`main`からCloudflare Pagesの本番サイトへ反映。

- 運営者専用の管理画面・ローカル座標設定GUIは**MVPに含めない**。
- Cloudflare Pagesの**PRプレビューデプロイは無効**にする。Cloudflare Accessも導入しない。
- GitHub Actionsの必須チェックとPR経由の変更を採用する。一人運営のため「自分自身のPRに他者の承認必須」を課す設計にはしない。運営者の目視確認は運用チェックリストで実施する。
- GitHub ActionsやCloudflare Pagesの無料枠・設定は公開時に再確認する。

## 9. 技術構成【実装方針】

| 分野 | 採用方針 |
|---|---|
| ページ・静的生成 | Astro |
| 編集画面 | React Islands + TypeScript |
| UI | Tailwind CSS v4、必要な場所のみCSS Modules／shadcn/ui |
| 画像描画 | Canvas 2Dを基本。縦書きの組版方式は技術検証で決定 |
| 下書き | IndexedDB |
| ソース管理 | GitHub Public + PR |
| CI | GitHub Actions（必要な箇所にPlaywrightを使用） |
| 配信 | Cloudflare Pages、`main`本番デプロイのみ |
| アクセス解析 | 無料・プライバシー重視の解析を導入。Cloudflare Web Analyticsを第一候補 |

アクセス解析を導入しても、カードに入力された文字・利用者のアイコン・下書きデータを収集・送信しない。ページ閲覧等の計測情報についてはプライバシーポリシーで説明し、URLに入力情報を含めない。

## 10. 非機能要件と安全性

- **アクセシビリティ:** WCAG 2.2 AAを目標とし、ラベル・キーボード操作・フォーカス・タッチ領域・エラー表示を考慮する。Canvasの移動操作にはボタン等の代替方法を提供する。
- **性能:** スマホの入力・ドラッグに対する追従性を優先。定量的な閾値は実機計測後に設定する。フォント・画像・描画の不要な読み込みを減らす。
- **セキュリティ:** 画像形式・デコード結果の検証、XSS予防、外部リンクの安全な扱い、依存関係の更新。利用者が明示的に共有操作を行った場合を除き、利用者画像を外部へ送信しない。
- **プライバシー:** 入力内容はブラウザ内に保存。解析はページ情報等に限定。プライバシーポリシーで例外を明示する。
- **保守:** テンプレート設定と描画処理を分離。安定IDとスキーマバージョンを持たせる。

## 11. MVP対象外

- 一般ユーザーによるテンプレート投稿、作者用管理機能
- 会員登録、クラウド保存、端末間同期、サーバーDB
- X APIやXアバター自動取得、自動投稿
- 管理GUI、Cloudflare PRプレビュー、複雑なアクセス制御
- 複数下書き、編集データのファイル入出力、履歴管理／Undo・Redo
- 画像生成AI、スタンプ追加、広告、課金、公開ギャラリー
- テンプレートレイヤーを利用者が自由編集する機能

## 12. MVP受け入れ条件

- [ ] 初回アクセス時にテンプレートを選択でき、作者情報・リンクが両画面で確認できる。
- [ ] Android Chrome、iPhone Safari、主要PCブラウザで基本フローが成立する。
- [ ] 文字、選択項目、円形アイコンが編集できる。スマホでスクロールと編集が競合しない。
- [ ] テンプレートで指定された縦書き・横書きが正しく表示される。
- [ ] 日本語入力と手動・自動改行が機能する。入力確定後のプレビューとPNGの配置が一致する。
- [ ] 自動縮小、フォント選択、色・揃え・位置調整、はみ出し警告が動作する。
- [ ] テンプレートの元画像サイズでPNGを保存できる。背景・アイコン・文字・前面装飾の描画が正しい。
- [ ] 下書きを自動保存し、再訪問で自動復元できる。保存失敗は通知される。
- [ ] PNG保存が常に可能で、共有非対応環境でも代替操作ができる。
- [ ] 許諾済みのテンプレートがPR・CI・人の目視確認を経て公開できる。
- [ ] 利用規約、プライバシーポリシー、作者クレジットが整備されている。
- [ ] WCAG 2.2 AAを目標としたチェックを実施し、重大な操作阻害が解消されている。

## 13. 開発時に判断する事項（要件定義を再開しなくてよい）

1. **縦書き描画エンジン:** Canvas単独／DOM・SVG併用。まず小さな技術検証で文字組み・PNG化を比較する。
2. **テンプレートと下書きの厳密な型・スキーマ:** 実装時に型検証を作成。ID維持、最小限の互換性、破壊的な上書き防止を必須とする。
3. **フォントの正式名称・容量・ライセンス表記:** 8〜10種の要件を満たして選定する。
4. **画像の縮小・メモリ保護閾値:** 3072pxを暫定値として端末別に検証。
5. **CIの画像比較・性能基準:** まず基本的な成功・失敗検証を実装し、必要な範囲で強化する。
6. **SNS共有のOS・ブラウザ差:** 実機確認と代替操作で吸収する。
7. **アクセス解析の実際の設定:** 無料・プライバシー要件に合うことを確認してから導入。

いずれも技術上の実現性が要件に影響する場合は、機能を黙って削るのではなく、変更案と理由を提示して合意を得る。

## 14. 推奨実装順（計画であり機能変更ではない）

1. 縦書き・横書き・改行・PNG生成の小規模技術検証。
2. 許諾済みのテンプレート1件で編集からPNG保存まで縦断的に実装。
3. アイコン調整、フォント、スマホUI、下書き、共有の順にMVP機能を完成。
4. GitHub PR・自動検証・確認画像を整え、複数テンプレート登録へ拡張。
5. 実機確認・権利表記・アクセス解析・本番公開。
