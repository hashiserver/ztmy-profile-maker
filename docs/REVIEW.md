# 自己紹介カードメーカー — MVP要件定義 再レビュー

- 対象: `SPEC.md` v1.8
- 日付: 2026-10-16
- 結論: **MVP開発に進める要件水準。詳細な未決事項の追加質問は不要。**
- 実装状況: 未着手。以下は設計レビューであり、動作検証結果ではない。

## 1. レビュー総評

サービスの価値、ユーザー体験、テンプレート追加方法、公開・権利処理が決まっている。開発前に全パラメータを決めるより、**縦書き＋日本語入力＋PNG出力の小規模技術検証**を先に行う方がリスクを効率的に下げられる。

一方、MVPの機能数は一般的な最小試作より多めである（縦書き、9種前後のフォント、アイコンのピンチ調整、IndexedDB、X共有、CI）。要求は変更せず、最初の1テンプレートで主要経路を通したあとに周辺機能を拡張する。

## 2. 方針の矛盾・重複を解消

| 以前の記述 | 最新の確定仕様 |
|---|---|
| 利用者が縦横方向を切り替える | **運営者がテンプレート／フィールド単位で指定**。利用者は変更しない |
| ローカルのフル機能座標設定GUIを作る | **作らない**。ChatGPT/Codexが画像から定義を作成し、PRを作る |
| Cloudflare Access付きのPRプレビューを作る | **作らない**。CI確認画像＋必要時のローカル検証 |
| X／unavatarから利用者アイコンを取得 | **取得しない**。端末からアップロード |
| 2048pxの画像正規化上限案 | **3072pxを暫定目安**（制限値は実機検証後） |
| 作者から前面装飾の分離を必須とする | **背景1枚が基本**。前面装飾は任意 |
| PRの作成者自身がGitHub上で承認する | **運営者が目視確認してマージ**。一人運営で形式的な他者承認を必須としない |

## 3. 優先度別の指摘

### P0 — 実装開始時に先に検証

**R-01 縦書きの品質とPNGへの描画（技術的な最大リスク）**
- Canvas 2Dの文字方向設定は主に左右方向で、CSSの縦書き組版機能そのものではない。
- 記号の向き、縦中横、行送り、文字幅、フォント差、Canvas出力をまとめて小規模検証する。
- **判定:** 実際の日本語・数字・英単語・括弧を含むサンプルで、プレビューとPNGが実用上整合すること。方式を先に固定しない。

**R-02 日本語IMEとプレビュー操作**
- HTML入力欄とCanvasの文字組み・キャレット挙動を無条件に一致させるのは難しい。
- 日本語変換中は標準HTML入力を壊さず、**変換確定後のプレビューとPNGの一致**を受け入れ基準にする。
- モバイルは下部入力パネルを基本とし、縦書きの直接キャレット配置までMVPの必須要件にしない。

**R-03 画像の掲載許諾・公開GitHubの範囲**
- Webサイトへの掲載許可だけで、公開GitHubでのファイル公開やユーザーの画像加工・SNS投稿まで網羅されるとは限らない。
- **対応:** 公開GitHubでの公開も含めて許諾を確認し、PRに入れる前に権利確認する。許諾の原文・DM等はコミットしない。

### P1 — 実装設計時に対処

**R-04 アイコン枠と前面装飾の重なり**
- 背景1枚に枠線・「アイコン」等の案内文字が焼き込まれていると、上から描くアップロード画像が枠や文字を覆うことがある。
- **対応:** アイコン表示領域を内側に収めるか、許諾済みの前面装飾レイヤーを追加し、PR確認画像で目視する。

**R-05 下書きの消失と更新時互換性**
- IndexedDBは永続保管を保証しない。画像Blobによる容量圧迫やテンプレート更新時のフィールド変更も問題になる。
- **対応:** 自動保存の成否を明示し、復元完了前の空データ上書きを防止。IDとバージョンを管理し、互換性不明なら上書きしない。

**R-06 無制限画像アップロードという誤解**
- ファイルのMB数とデコード後の画素数・メモリは別。端末によっては巨大画像で処理が停止する。
- **対応:** 容量による一律拒否を避けつつ、形式・寸法・デコード失敗を検出。3072pxは作業画像の暫定目安。テンプレート自体の高解像度PNGも検証する。

**R-07 フォント9種類と通信量**
- 日本語フォントを一括配信すると初期読み込みが重くなり得る。
- **対応:** 利用中のフォントを遅延ロードし、各フォントの同梱・サブセット・ライセンス条件を確認する。9件は候補であり検証前に正式確定としない。

**R-08 X共有の保証範囲**
- Web Share APIのファイル対応、OSの共有先、Xアプリの画像・文章受け取りは環境差がある。Xの投稿リンクだけで画像は自動添付できない。
- **対応:** PNGダウンロードを常に可能にし、文章コピー・画像コピー・X投稿画面への遷移を分離して用意する。

**R-09 CIで検証できること／できないこと**
- JSONが正しくても、領域位置や文字が自然かは機械判定できない。公開リポジトリではPR/成果物も第三者から見える。
- **対応:** スキーマ・ビルド・描画成功を自動検証。領域付き確認画像・通常入力画像を出力し、運営者の目視チェックを必須とする。

### P2 — 公開前の確認

**R-10 アクセシビリティ**
- Canvasだけに機能を閉じるとキーボードや支援技術では使いづらい。
- **対応:** フィールド選択・文字編集・位置の微調整をフォームとボタンでも操作可能にする。WCAG 2.2 AAを目標にチェックする。

**R-11 解析とプライバシー表現**
- 「編集画像は外へ送らない」と「解析サービスは外部へページ情報を送る」を混同しない。
- **対応:** 編集内容は収集しない一方、アクセス解析の収集対象・サービスをプライバシーポリシーで説明する。入力値をURLへ含めない。

**R-12 無料運用の保証はしない**
- サービスの無料枠・公開条件は変わり得る。
- **対応:** 月額0円を目標とし、GitHub ActionsとCloudflare Pagesの使用量・設定を公開時に確認する。

## 4. MVP範囲の適切性

### 残すべき機能

テンプレート選択、作者情報、文字入力、縦横両対応（運営者指定）、自動縮小と警告、アイコン画像アップロード・円形調整、PNG保存、下書き自動復元、X共有の代替操作。これらは既に決定されており、変更しない。

### 実装では省略・後回しにしてよい作り込み

- 一般ユーザー／運営者の管理画面
- GUIでのテンプレート座標作成
- PRごとのCloudflare Previewサイト
- 高度な画像差分テスト、全ブラウザ全フォントの網羅的な組合せテスト
- 多段階の下書きマイグレーション基盤
- 画像の複雑なメモリ予測ロジック
- 編集データのファイルエクスポート／複数下書き

後回しとは**決定済みのMVP機能の削除ではなく、内部実装の高度化を必要最小限にすること**を意味する。

## 5. 推奨作業順と判断ゲート

1. **技術検証:** 縦書き・横書き、IME、入力確定後のプレビュー、PNG出力を最小構成で確認。
2. **最初の1テンプレート:** 許諾済みの画像でカード編集→PNG保存を完成。
3. **操作性と保存:** スマホ入力、アイコンの切り抜き、自動保存・復元を追加。
4. **フォント・共有:** 8〜10種のフォントを確認し、共有・代替操作を実装。
5. **テンプレート運用:** AIによるPR、CI確認画像、運営者レビューを整備。
6. **公開:** 権利・アクセシビリティ・端末・解析設定を確認し本番公開。

**実装を始める前に必ずユーザーへ再確認すべきものは、新たに機能の削除・要件変更が必要と判明したときのみ。** スキーマの型やCIツール選定などは開発時に決めて記録してよい。
